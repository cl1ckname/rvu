## Модель данных

```rust
struct Changeset {
    files: Vec<FileDiff>,
    refs: Option<DiffRefs>,        // base/start/head sha — нужны для GitLab
}

struct FileDiff {
    old_path: Option<PathBuf>,     // None — файл добавлен
    new_path: Option<PathBuf>,     // None — файл удалён
    status: FileStatus,            // Added / Deleted / Modified / Renamed / Binary
    hunks: Vec<Hunk>,
    // Полные версии нужны режиму Page; грузятся лениво.
    old_content: Lazy<Option<String>>,
    new_content: Lazy<Option<String>>,
}

struct Hunk { old_start, old_len, new_start, new_len, header, lines: Vec<DiffLine> }

struct DiffLine {
    kind: LineKind,                // Context / Added / Removed
    old_lineno: Option<u32>,
    new_lineno: Option<u32>,
    content: String,
}
```

**Позиция строки** (`LineRef`) = файл + `old_lineno` и/или `new_lineno`.
Модель позиции совпадает с моделью GitLab (`old_line` / `new_line` +
`diff_refs`). Поэтому одна и та же позиция подходит и для вставки локального
комментария, и для отправки комментария в MR:

| Строка    | old_lineno | new_lineno | GitLab                    | Локальная вставка                |
|-----------|------------|------------|---------------------------|----------------------------------|
| Context   | ✔          | ✔          | `old_line` + `new_line`   | над `new_lineno`                 |
| Added     | —          | ✔          | `new_line`                | над `new_lineno`                 |
| Removed   | ✔          | —          | `old_line`                | над следующей существующей строкой |

## Режимы отображения

Оба режима строят из модели плоский список `RenderLine` (строка кода с
номерами, видом и подсветкой, либо служебная строка: заголовок файла,
заголовок ханка). Курсор и скролл работают по индексу в этом списке, а у
каждой строки кода есть `LineRef`. Поэтому навигация и комментирование
не зависят от режима.

- **Scroll:** для каждого файла — заголовок файла + ханки.
  Файлы идут в порядке дерева (каталоги первыми), чтобы движение по дереву
  и по диффу совпадало.
- **Page:** один файл: новая версия целиком, удалённые строки вклеены
  перед строкой, которая идёт за ними. Строки вне ханков — `Row::FileLine`
  с номерами в обеих версиях (номер в старой версии вычисляется из сдвига,
  накопленного предыдущими ханками). Для удалённого файла показываются
  только ханки.

Сворачивание (Page): неизменённые строки дальше `fold_context` строк от
ближайшего изменения заменяются одной `Row::Fold` с номерами первой скрытой
строки и их количеством. Участок из одной строки не сворачивается.

При смене режима, перезагрузке и т.п. позиция запоминается как
«путь файла + (old, new) номера строки» и ищется в новом списке строк
(`DiffView::find_line`; если точной строки нет — ближайшая строка файла).

## Подсветка

Подсвечивается целый файл (старая и новая версия отдельно), лениво — когда
строки файла впервые попадают на экран. При отрисовке строка из кэша
используется, только если её текст совпадает с текстом строки диффа; иначе
(файл поменялся на диске, не тот номер строки) строка рисуется без подсветки.
Файлы больше 1 МБ не подсвечиваются.

## Event loop

`tokio` + `crossterm::event::EventStream`. Источники событий объединяются
в один канал: клавиатура, resize, результаты фоновых задач (загрузка диффа,
ответы GitLab). Сетевые запросы выполняются в `tokio::spawn` и не блокируют
отрисовку.
